# CAE-MVP — двумерный конечно-элементный решатель

Учебно-исследовательский прототип CAE (Computer-Aided Engineering) на **C++20 и Eigen**. Проект преобразует двумерную геометрию в треугольную сетку, формирует дискретные уравнения методом конечных элементов (МКЭ), решает разреженные системы и экспортирует поля в VTK для **ParaView**.

## Что реализовано

- Геометрия: прямоугольник, окружность, прямоугольник с отверстием; контуры из отрезков и дуг.
- Сетка: узлы, линейные треугольники, граничные рёбра и маркеры; генератор прямоугольной сетки, импорт VTK (разбиение сетки реализовано только для прямоугольной геометрии).
- МКЭ: треугольники **P1** и **P2**, барицентрические функции формы, численное интегрирование; отображения степеней свободы P2 и Taylor–Hood P2/P1.
- Стационарная теплопроводность: объёмные источники, условия Дирихле, Неймана и Робина.
- Нестационарная гидродинамика: несжимаемая жидкость, массовая и вязкостная матрицы, связь скорости и давления, конвекция в форме линеаризации по предыдущему полю скорости, временные шаги.
- Разреженная сборка через `Eigen::Triplet`, прямое решение с помощью Eigen, VTK-вывод.

Это **MVP**, а не промышленный CAE-пакет: нет общего GUI, автоматической адаптивной сетки, развитого контроля качества, универсального 3D-решателя или полного набора регрессионных тестов.

## Математические модели

**Теплопроводность (стационарная):**

$$
-\nabla\cdot(\lambda\nabla T)=f\quad\text{в }\Omega.
$$

**Несжимаемая гидродинамика:**

$$
\rho\left(\frac{\partial\mathbf u}{\partial t}+(\mathbf u\cdot\nabla)\mathbf u\right)-\nabla\cdot(2\mu D(\mathbf u))+\nabla p=\mathbf f,\qquad\nabla\cdot\mathbf u=0,
$$

где $D(\mathbf u)=(\nabla\mathbf u+\nabla\mathbf u^T)/2$. Для скорости используются P2-функции формы, для давления — P1.

```text
CAE-MVP/
├── geometry/               геометрические примитивы и контуры
├── mesh/                   топология сетки и граничные метки
│   └── generators/         построение треугольных сеток
├── fem/
│   ├── elements/           P1/P2, функции формы, квадратуры
│   ├── dofs/               глобальная нумерация степеней свободы

├── physics/
│   ├── heat/               постановка и решение теплопроводности
│   │   ├── problem/        параметры и граничные условия
│   │   └── assembly/       объёмная и граничная сборка
│   └── hydro/              постановка и решение гидродинамики
│       ├── problem/        физические параметры и колбэки
│       └── assembly/       массовая, вязкостная, конвективная сборка

├── solutions/              примеры рассчитанных полей
```

**Принцип зависимостей:** геометрия → сетка → элементы и DOF → физический ассемблер → решатель → экспорт. Обратных зависимостей физики от визуализации по возможности следует избегать.

## Сборка

Требуются CMake **3.20+**, компилятор с поддержкой **C++20**, **Eigen3**. На macOS подойдёт AppleClang; CUDA не требуется.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

Цели, объявленные в `CMakeLists.txt`:

- `cae_heat` — запуск `mainHeat.cpp`;
- `cae_hydro` — запуск `mainHydro.cpp`;
- статические библиотеки `cae_mesh`, `cae_fem`, `cae_io`, `cae_heat`, `cae_hydro` и интерфейсная `cae_geometry`.

Пример:

```bash
./build/cae_heat
./build/cae_hydro
```

**Важно:** `mainHydro.cpp` загружает `channel_hole_L006_under800.vtk` по относительному пути. Запускайте из корня проекта или исправьте путь. Аналогично пути вывода отсчитываются от рабочего каталога.

## Проверочные примеры

**Теплопроводность.** Прямоугольник $L=0.06$, $H=0.02$, $\lambda=10$; слева $T=100$, справа $T=200$, сверху и снизу нулевой поток. При нулевом источнике точное решение:

$$
T(x,y)=100+100x/L.
$$

`mainHeat.cpp` сравнивает численное решение с аналитическим и сохраняет `solutions/heat/temperature.vtk`.

**Гидродинамика.** `mainHydro.cpp` импортирует канал с круглым препятствием, маркирует границы, задаёт плотность, вязкость, входную скорость и параметры времени. `HydroSolver` экспортирует кадры и VTK-серию. В отличие от теплового примера, это демонстрационный сценарий, а не строгое аналитическое доказательство точности.

## Визуализация в ParaView

Откройте `.vtk` через **File → Open → Apply**. Для теплопроводности выберите поле температуры; для гидродинамики — поля скорости/давления из VTK. Для временной последовательности используйте `.vtk.series` и элементы управления временем. Подробности — [`io/README.md`](io/README.md).
